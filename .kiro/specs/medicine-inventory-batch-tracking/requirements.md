# Requirements Document

## Introduction

This feature extends the existing medicine inventory system in the RCMC EMR to support batch/lot tracking. Currently, the inventory treats each medicine name as a single record. This causes problems when the same medicine arrives in multiple shipments with different expiration dates and quantities — the system cannot distinguish between them.

The batch tracking system allows the same medicine to exist as multiple distinct records (batches), each with its own batch number, lot number, expiration date, manufacture date, and stock quantity. The UI must surface batch-level detail while still presenting a consolidated view per medicine name. The system must also proactively alert staff to expiring and expired stock.

The database migration script (`ADD_INVENTORY_BATCH_TRACKING.sql`) and guide (`INVENTORY_BATCH_TRACKING_GUIDE.md`) already exist and define the target schema. This spec formalizes the requirements and drives the UI/UX implementation.

---

## Glossary

- **Inventory_System**: The medicine inventory module in the RCMC EMR (`src/pages/Inventory.jsx` and `src/context/InventoryContext.jsx`)
- **Batch**: A single shipment lot of a medicine, uniquely identified by medicine name + batch number + expiration date
- **Batch_Number**: An alphanumeric identifier assigned by the manufacturer or auto-generated by the system
- **Lot_Number**: An optional secondary identifier from the manufacturer
- **Expiration_Date**: The date after which a batch is considered expired and must not be dispensed
- **Manufacture_Date**: The date the batch was produced
- **FIFO**: First In, First Out — dispensing the batch with the earliest expiration date first
- **Expiring_Soon**: A batch whose expiration date falls within 30 days from the current date
- **Expired**: A batch whose expiration date is before the current date
- **Inventory_Summary**: An aggregated view of total stock across all batches for a given medicine name
- **Batch_Detail_View**: A UI panel showing all individual batches for a selected medicine

## Requirements

### Requirement 1: Batch-Level Data Model

**User Story:** As a pharmacist, I want to record the same medicine multiple times with different batch numbers and expiration dates, so that I can track each shipment separately.

#### Acceptance Criteria

1. THE Inventory_System SHALL store each batch as a distinct record identified by the combination of medicine name, batch number, and expiration date.
2. THE Inventory_System SHALL store the following fields per batch: `batch_number`, `lot_number`, `expiration_date`, `manufacture_date`, and `stock`.
3. WHEN a batch record is saved without a batch number, THE Inventory_System SHALL auto-generate a batch number in the format `BATCH-{timestamp}-{random}`.
4. THE Inventory_System SHALL enforce uniqueness on the combination of name + batch_number + expiration_date, allowing NULL values in either batch_number or expiration_date to be handled via partial unique indexes.
5. IF a user attempts to save a batch that duplicates an existing name + batch_number + expiration_date combination, THEN THE Inventory_System SHALL display an error message identifying the conflicting fields.

---

### Requirement 2: Batch Status Auto-Management

**User Story:** As a pharmacist, I want the system to automatically set the status of each batch based on its expiration date and stock level, so that I do not have to manually update statuses.

#### Acceptance Criteria

1. WHEN a batch record is inserted or updated, THE Inventory_System SHALL automatically set the status to `Expired` if the expiration date is before the current date.
2. WHEN a batch record is inserted or updated, THE Inventory_System SHALL automatically set the status to `Expiring Soon` if the expiration date is within 30 days from the current date and has not yet passed.
3. WHEN a batch record is inserted or updated and the expiration date is more than 30 days away, THE Inventory_System SHALL set the status to `Out of Stock` if stock equals zero, `Low Stock` if stock is at or below the reorder level, or `In Stock` otherwise.
4. THE Inventory_System SHALL apply status auto-management via a database trigger that fires on INSERT and UPDATE of the `stock`, `expiration_date`, and `reorder_level` fields.

---

### Requirement 3: Consolidated Medicine View (Inventory Summary)

**User Story:** As a pharmacist, I want to see a single row per medicine name showing total stock across all batches, so that I can quickly assess overall availability without being overwhelmed by individual batch rows.

#### Acceptance Criteria

1. THE Inventory_System SHALL display a summary list where each row represents a unique medicine name.
2. THE Inventory_System SHALL display the total stock quantity summed across all batches for each medicine name in the summary list.
3. THE Inventory_System SHALL display the number of active batches for each medicine name in the summary list.
4. THE Inventory_System SHALL display the earliest expiration date across all batches for each medicine name in the summary list.
5. WHEN a medicine has at least one batch with status `Expired` or `Expiring Soon`, THE Inventory_System SHALL visually highlight that medicine row in the summary list with a warning indicator.

---

### Requirement 4: Batch Detail View

**User Story:** As a pharmacist, I want to expand a medicine row to see all its individual batches with their quantities and expiration dates, so that I can manage stock at the batch level.

#### Acceptance Criteria

1. WHEN a user selects a medicine in the summary list, THE Inventory_System SHALL display a batch detail panel listing all batches for that medicine.
2. THE Inventory_System SHALL display the following fields for each batch in the detail panel: batch number, lot number, stock quantity, expiration date, manufacture date, and status.
3. THE Inventory_System SHALL sort batches in the detail panel by expiration date in ascending order (earliest first, consistent with FIFO).
4. THE Inventory_System SHALL allow the user to add a new batch for the selected medicine directly from the batch detail panel.
5. THE Inventory_System SHALL allow the user to edit an existing batch from the batch detail panel.
6. THE Inventory_System SHALL allow the user to delete a batch from the batch detail panel, with a confirmation prompt before deletion.

---

### Requirement 5: Add and Edit Batch Form

**User Story:** As a pharmacist, I want a form to add or edit a batch with all relevant fields, so that I can accurately record incoming stock.

#### Acceptance Criteria

1. THE Inventory_System SHALL provide a form with the following fields for adding or editing a batch: medicine name, category, unit, price, supplier, stock quantity, reorder level, batch number, lot number, expiration date, and manufacture date.
2. WHEN adding a new batch, THE Inventory_System SHALL pre-populate the medicine name, category, unit, price, and supplier fields if the medicine already exists in the system.
3. THE Inventory_System SHALL require medicine name, stock quantity, reorder level, unit, price, and expiration date as mandatory fields.
4. WHEN the expiration date field is left blank on form submission, THE Inventory_System SHALL display a validation error indicating that expiration date is required.
5. WHEN the batch number field is left blank on form submission, THE Inventory_System SHALL auto-generate a batch number before saving.

---

### Requirement 6: Expiry Monitoring and Alerts

**User Story:** As a pharmacist, I want to see a dedicated view of expiring and expired batches, so that I can take action before medicines become unusable.

#### Acceptance Criteria

1. THE Inventory_System SHALL provide an expiry monitoring section that lists all batches expiring within 90 days from the current date.
2. THE Inventory_System SHALL display the number of days until expiry for each batch in the expiry monitoring section.
3. THE Inventory_System SHALL provide a separate view for expired batches that still have stock greater than zero.
4. THE Inventory_System SHALL display a summary count of expiring-soon batches and expired batches in the inventory statistics cards at the top of the page.
5. WHEN the inventory page loads, THE Inventory_System SHALL query the `expiring_inventory` and `expired_inventory` database views to populate the expiry monitoring sections.

---

### Requirement 7: Search and Filter with Batch Awareness

**User Story:** As a pharmacist, I want to search and filter inventory by medicine name, category, status, and expiry, so that I can quickly find the batches I need.

#### Acceptance Criteria

1. WHEN a user enters a search term, THE Inventory_System SHALL filter the summary list to show only medicines whose name or supplier contains the search term (case-insensitive).
2. WHEN a user selects a category filter, THE Inventory_System SHALL filter the summary list to show only medicines in the selected category.
3. WHEN a user selects a status filter, THE Inventory_System SHALL filter the summary list to show medicines that have at least one batch matching the selected status.
4. THE Inventory_System SHALL provide a filter option for `Expiring Soon` and `Expired` statuses in addition to the existing stock-level statuses.
5. WHEN a user applies a status filter of `Expiring Soon` or `Expired`, THE Inventory_System SHALL highlight the matching batches within the batch detail panel of each returned medicine.

---

### Requirement 8: FIFO Dispensing Guidance

**User Story:** As a pharmacist, I want the system to indicate which batch to dispense first, so that I can follow FIFO and minimize medicine waste.

#### Acceptance Criteria

1. THE Inventory_System SHALL visually mark the batch with the earliest expiration date as the recommended dispense batch within the batch detail panel.
2. WHEN multiple batches share the same earliest expiration date, THE Inventory_System SHALL mark all tied batches as recommended.
3. THE Inventory_System SHALL display a FIFO indicator label (e.g., "Dispense First") on the recommended batch row.

---

### Requirement 9: CSV Import with Batch Support

**User Story:** As a pharmacist, I want to import a CSV file containing multiple rows for the same medicine with different batch numbers and expiration dates, so that I can bulk-load batch data efficiently.

#### Acceptance Criteria

1. THE Inventory_System SHALL accept CSV files containing the columns: `item_name`, `price`, `stock`, `unit`, `batch_number`, `expiration_date`, and optionally `lot_number` and `manufacture_date`.
2. WHEN a CSV row contains a medicine name and batch number combination that already exists in the database with the same expiration date, THE Inventory_System SHALL treat it as a duplicate and skip the row, reporting it in the import results.
3. WHEN a CSV row contains a medicine name and batch number combination that already exists but with a different expiration date, THE Inventory_System SHALL treat it as a new batch and insert it.
4. WHEN a CSV row is missing a batch number, THE Inventory_System SHALL auto-generate one before inserting.
5. THE Inventory_System SHALL display an import summary showing the count of rows inserted, skipped as duplicates, and failed with errors.
