# Requirements Document: Revenue Insights Dashboard Component

## Introduction

This feature implements a comprehensive Revenue Insights dashboard component that provides multi-dimensional revenue analysis through six distinct views: Department Revenue, Service Types, Payment Methods, Doctor Performance, Inventory Costs, and Patient Types. The component displays revenue data in an interactive tabbed interface with a horizontal bar chart visualization, showing total revenue with period-over-period comparison and supporting data export functionality. The dashboard integrates into the existing Reports page Analytics tab and fetches all data from the Supabase database.

## Glossary

- **Revenue_Insights_Component**: The main dashboard component displaying revenue analysis across multiple dimensions
- **View_Tab**: A selectable tab representing one of six revenue analysis perspectives
- **Department_Revenue_View**: Revenue breakdown by hospital departments (e.g., Emergency, Cardiology, Pediatrics)
- **Service_Type_View**: Revenue breakdown by service categories (e.g., Consultations, Laboratory, Imaging)
- **Payment_Method_View**: Revenue distribution by payment methods (e.g., Cash, Credit Card, Insurance)
- **Doctor_Performance_View**: Revenue generated by individual doctors
- **Inventory_Costs_View**: Cost analysis of inventory items used in patient care
- **Patient_Type_View**: Revenue breakdown by patient categories (e.g., New vs Returning, Inpatient vs Outpatient)
- **Horizontal_Bar_Chart**: A bar chart with horizontal orientation showing revenue values with labels
- **Total_Revenue_Display**: A prominent display showing aggregate revenue for the selected view
- **Period_Comparison**: Percentage change indicator comparing current period to previous period
- **No_Data_State**: A placeholder display shown when no data is available for the selected view
- **Export_Menu**: A dropdown menu providing data export options
- **Database_Query**: A Supabase query retrieving revenue data from hospital tables
- **View_Selector**: The tab navigation component allowing users to switch between revenue views

## Requirements

### Requirement 1: Revenue Insights Component Structure

**User Story:** As a hospital administrator, I want to see a Revenue Insights section in the Analytics dashboard, so that I can analyze revenue from multiple perspectives.

#### Acceptance Criteria

1. THE Revenue_Insights_Component SHALL be displayed in the Analytics tab of the Reports page
2. THE Revenue_Insights_Component SHALL render as a white card with rounded corners and shadow
3. THE Revenue_Insights_Component SHALL display "Revenue Insights" as the section title with an icon
4. THE Revenue_Insights_Component SHALL include a three-dot menu button in the top-right corner
5. THE Revenue_Insights_Component SHALL display six View_Tab buttons below the title
6. THE Revenue_Insights_Component SHALL display the Total_Revenue_Display prominently
7. THE Revenue_Insights_Component SHALL display the Period_Comparison below the total revenue
8. THE Revenue_Insights_Component SHALL display either a Horizontal_Bar_Chart or No_Data_State

### Requirement 2: View Tab Navigation

**User Story:** As a user, I want to switch between different revenue analysis views, so that I can explore revenue from various dimensions.

#### Acceptance Criteria

1. THE View_Selector SHALL display six View_Tab buttons: Department Revenue, Service Types, Payment Methods, Doctor Performance, Inventory Costs, Patient Types
2. WHEN the component loads, THE View_Selector SHALL set "Department Revenue" as the default active tab
3. WHEN a user clicks a View_Tab, THE Revenue_Insights_Component SHALL update the active view state
4. WHEN a View_Tab is active, THE View_Tab SHALL display with teal background (#14B8A6) and white text
5. WHEN a View_Tab is inactive, THE View_Tab SHALL display with light gray background and dark text
6. THE View_Tab SHALL display an icon representing the view type (e.g., Building2 for Department)
7. THE View_Tab SHALL be keyboard accessible with tab and enter key navigation

### Requirement 3: Department Revenue View

**User Story:** As a hospital administrator, I want to see revenue breakdown by department, so that I can identify which departments generate the most revenue.

#### Acceptance Criteria

1. WHEN "Department Revenue" tab is selected, THE Revenue_Insights_Component SHALL query consultations table grouped by department
2. THE Database_Query SHALL join consultations with payments table to calculate revenue per department
3. THE Database_Query SHALL filter by the selected date range from Date_Range_Filter
4. THE Horizontal_Bar_Chart SHALL display departments sorted by revenue in descending order
5. THE Horizontal_Bar_Chart SHALL show department names on the Y-axis
6. THE Horizontal_Bar_Chart SHALL show revenue amounts on the X-axis with currency formatting
7. THE Horizontal_Bar_Chart SHALL display revenue values as labels at the end of each bar
8. THE Total_Revenue_Display SHALL show the sum of all department revenues

### Requirement 4: Service Type Revenue View

**User Story:** As a financial manager, I want to see revenue breakdown by service type, so that I can understand which services are most profitable.

#### Acceptance Criteria

1. WHEN "Service Types" tab is selected, THE Revenue_Insights_Component SHALL query payments table grouped by service type
2. THE Database_Query SHALL categorize services into: Consultations, Laboratory Tests, Imaging, Procedures, Medications, Room Charges
3. THE Database_Query SHALL sum revenue for each service category from billing items
4. THE Horizontal_Bar_Chart SHALL display service types sorted by revenue in descending order
5. THE Horizontal_Bar_Chart SHALL use distinct colors for each service type
6. THE Total_Revenue_Display SHALL show the sum of all service type revenues

### Requirement 5: Payment Method Distribution View

**User Story:** As a financial manager, I want to see revenue distribution by payment method, so that I can understand payment preferences and optimize payment processing.

#### Acceptance Criteria

1. WHEN "Payment Methods" tab is selected, THE Revenue_Insights_Component SHALL query payments table grouped by payment_method
2. THE Database_Query SHALL aggregate revenue for each payment method: Cash, Credit Card, Debit Card, Insurance, Bank Transfer
3. THE Database_Query SHALL calculate percentage of total revenue for each payment method
4. THE Horizontal_Bar_Chart SHALL display payment methods sorted by revenue in descending order
5. THE Horizontal_Bar_Chart SHALL show both revenue amount and percentage in the tooltip
6. THE Total_Revenue_Display SHALL show the sum of all payment method revenues

### Requirement 6: Doctor Performance View

**User Story:** As a hospital administrator, I want to see revenue generated by each doctor, so that I can recognize high-performing physicians and identify training needs.

#### Acceptance Criteria

1. WHEN "Doctor Performance" tab is selected, THE Revenue_Insights_Component SHALL query consultations table grouped by doctor_id
2. THE Database_Query SHALL join consultations with user_profiles table to get doctor names
3. THE Database_Query SHALL join consultations with payments table to calculate revenue per doctor
4. THE Database_Query SHALL include only completed consultations with associated payments
5. THE Horizontal_Bar_Chart SHALL display doctor names sorted by revenue in descending order
6. THE Horizontal_Bar_Chart SHALL show patient count for each doctor in the tooltip
7. THE Total_Revenue_Display SHALL show the sum of all doctor-generated revenues

### Requirement 7: Inventory Costs Analysis View

**User Story:** As a financial manager, I want to see inventory costs breakdown, so that I can identify high-cost items and optimize inventory management.

#### Acceptance Criteria

1. WHEN "Inventory Costs" tab is selected, THE Revenue_Insights_Component SHALL query inventory table joined with billing items
2. THE Database_Query SHALL calculate total cost for each inventory item used during the selected period
3. THE Database_Query SHALL include quantity used and unit cost for each item
4. THE Horizontal_Bar_Chart SHALL display inventory items sorted by total cost in descending order
5. THE Horizontal_Bar_Chart SHALL show quantity used in the tooltip
6. THE Total_Revenue_Display SHALL show the sum of all inventory costs
7. THE Period_Comparison SHALL show cost increase or decrease from previous period

### Requirement 8: Patient Type Revenue View

**User Story:** As a hospital administrator, I want to see revenue breakdown by patient type, so that I can understand revenue sources and tailor services accordingly.

#### Acceptance Criteria

1. WHEN "Patient Types" tab is selected, THE Revenue_Insights_Component SHALL query patients table joined with payments
2. THE Database_Query SHALL categorize patients into: New Patients, Returning Patients, Inpatients, Outpatients, Emergency Patients
3. THE Database_Query SHALL calculate revenue for each patient category
4. THE Horizontal_Bar_Chart SHALL display patient types sorted by revenue in descending order
5. THE Horizontal_Bar_Chart SHALL show patient count for each category in the tooltip
6. THE Total_Revenue_Display SHALL show the sum of all patient type revenues

### Requirement 9: Total Revenue Display

**User Story:** As a user, I want to see the total revenue prominently displayed, so that I can quickly understand the overall revenue for the selected view.

#### Acceptance Criteria

1. THE Total_Revenue_Display SHALL show "Total Revenue" as the label
2. THE Total_Revenue_Display SHALL display the revenue amount in Philippine Peso format (₱)
3. THE Total_Revenue_Display SHALL format amounts with thousands separators (e.g., ₱1,234,567.89)
4. THE Total_Revenue_Display SHALL display amounts with 2 decimal places
5. THE Total_Revenue_Display SHALL update dynamically when the active view changes
6. THE Total_Revenue_Display SHALL update dynamically when the date range changes

### Requirement 10: Period-over-Period Comparison

**User Story:** As a hospital administrator, I want to see how revenue has changed compared to the previous period, so that I can track growth trends.

#### Acceptance Criteria

1. THE Period_Comparison SHALL calculate the percentage change from the previous period
2. THE Period_Comparison SHALL define previous period as an equal-length period immediately before the selected date range
3. WHEN revenue increases, THE Period_Comparison SHALL display a green upward arrow icon with percentage
4. WHEN revenue decreases, THE Period_Comparison SHALL display a red downward arrow icon with percentage
5. WHEN previous period revenue is zero, THE Period_Comparison SHALL display "Significant Change" in amber color
6. THE Period_Comparison SHALL display the text "from previous period" after the percentage
7. THE Period_Comparison SHALL format percentage with 1 decimal place (e.g., "12.5% increase")

### Requirement 11: Horizontal Bar Chart Visualization

**User Story:** As a user, I want to see revenue data in a horizontal bar chart, so that I can easily compare values across categories.

#### Acceptance Criteria

1. THE Horizontal_Bar_Chart SHALL use Recharts library for rendering
2. THE Horizontal_Bar_Chart SHALL display category names on the Y-axis with 150px width
3. THE Horizontal_Bar_Chart SHALL display revenue amounts on the X-axis with currency formatting
4. THE Horizontal_Bar_Chart SHALL format X-axis labels as: ₱1M for millions, ₱1K for thousands
5. THE Horizontal_Bar_Chart SHALL display bars with rounded corners (8px radius on right side)
6. THE Horizontal_Bar_Chart SHALL use teal color (#14B8A6) as default bar color
7. THE Horizontal_Bar_Chart SHALL display revenue values as labels at the end of each bar
8. THE Horizontal_Bar_Chart SHALL limit display to top 10 items sorted by revenue
9. THE Horizontal_Bar_Chart SHALL set height to 350px with responsive width

### Requirement 12: Chart Interactivity

**User Story:** As a user, I want to interact with the chart, so that I can see detailed information about each revenue category.

#### Acceptance Criteria

1. WHEN a user hovers over a bar, THE Horizontal_Bar_Chart SHALL display a custom tooltip
2. THE custom tooltip SHALL show the category name, revenue amount, and percentage of total
3. WHEN applicable, THE custom tooltip SHALL show additional metrics (e.g., patient count, quantity)
4. THE Horizontal_Bar_Chart SHALL display a CartesianGrid with horizontal lines only
5. THE Horizontal_Bar_Chart SHALL use smooth transitions when data updates
6. THE Horizontal_Bar_Chart SHALL maintain aspect ratio during window resize

### Requirement 13: No Data State

**User Story:** As a user, I want to see a clear message when no data is available, so that I understand the dashboard status.

#### Acceptance Criteria

1. WHEN no data exists for the selected view and date range, THE Revenue_Insights_Component SHALL display the No_Data_State
2. THE No_Data_State SHALL display an icon representing the current view (e.g., Building2 for Department)
3. THE No_Data_State SHALL display the text "No data available" in medium font weight
4. THE No_Data_State SHALL display the text "Data will appear here once available" in smaller font
5. THE No_Data_State SHALL center all content vertically and horizontally
6. THE No_Data_State SHALL use gray colors for text and icon

### Requirement 14: Export Functionality

**User Story:** As a user, I want to export revenue data to CSV, so that I can perform offline analysis or share reports.

#### Acceptance Criteria

1. WHEN a user clicks the three-dot menu button, THE Export_Menu SHALL display a dropdown
2. THE Export_Menu SHALL include an "Export Data" option with a download icon
3. WHEN a user clicks "Export Data", THE Revenue_Insights_Component SHALL generate a CSV file
4. THE CSV file SHALL include columns: Name, Amount, Percentage
5. THE CSV file SHALL include all data points from the current view (not just top 10)
6. THE CSV file SHALL include a total row at the bottom
7. THE CSV file SHALL be named with the view label and current date (e.g., "Department_Revenue_2025-01-15.csv")
8. WHEN export completes, THE browser SHALL trigger a file download

### Requirement 15: Date Range Integration

**User Story:** As a user, I want all revenue views to respect the selected date range, so that I can analyze specific time periods.

#### Acceptance Criteria

1. THE Revenue_Insights_Component SHALL receive date range from the parent Analytics dashboard
2. WHEN the date range changes, THE Revenue_Insights_Component SHALL re-fetch data for the active view
3. THE Database_Query SHALL include WHERE clauses filtering by created_at or date columns
4. THE Database_Query SHALL use the startDate as the lower bound (inclusive)
5. THE Database_Query SHALL use the endDate as the upper bound (inclusive)
6. THE Revenue_Insights_Component SHALL display a loading state while fetching filtered data

### Requirement 16: Responsive Design

**User Story:** As a user on any device, I want the Revenue Insights component to adapt to my screen size, so that I can view revenue analysis on desktop, tablet, or mobile.

#### Acceptance Criteria

1. WHEN viewport width is >= 640px, THE View_Tab SHALL display both icon and label text
2. WHEN viewport width is < 640px, THE View_Tab SHALL display only the icon
3. THE View_Selector SHALL wrap tabs to multiple rows on narrow screens
4. THE Horizontal_Bar_Chart SHALL resize dynamically to fit container width
5. THE Total_Revenue_Display SHALL remain readable at all screen sizes
6. THE Export_Menu SHALL position correctly relative to the three-dot button on all screen sizes

### Requirement 17: Performance Optimization

**User Story:** As a user, I want the Revenue Insights component to load quickly, so that I can access insights without delays.

#### Acceptance Criteria

1. WHEN a view tab is clicked, THE Revenue_Insights_Component SHALL fetch data within 500 milliseconds
2. THE Database_Query SHALL use indexed columns for WHERE and GROUP BY clauses
3. THE Revenue_Insights_Component SHALL cache data for each view during the current session
4. WHEN switching back to a previously viewed tab, THE Revenue_Insights_Component SHALL use cached data if date range unchanged
5. THE Horizontal_Bar_Chart SHALL render within 200 milliseconds after data is received

### Requirement 18: Error Handling

**User Story:** As a user, I want clear feedback when errors occur, so that I understand what went wrong and how to proceed.

#### Acceptance Criteria

1. WHEN a Database_Query fails, THE Revenue_Insights_Component SHALL log the error to the console
2. WHEN a Database_Query fails, THE Revenue_Insights_Component SHALL display the No_Data_State
3. WHEN a Database_Query times out, THE Revenue_Insights_Component SHALL retry once automatically
4. WHEN export fails, THE Revenue_Insights_Component SHALL display an error message in the Export_Menu
5. THE Revenue_Insights_Component SHALL continue functioning for other views when one view fails

### Requirement 19: Accessibility Compliance

**User Story:** As a user with disabilities, I want the Revenue Insights component to be accessible, so that I can use assistive technologies to view revenue analysis.

#### Acceptance Criteria

1. THE View_Tab SHALL include aria-label attributes describing the view name
2. THE three-dot menu button SHALL include aria-label "Revenue insights chart options"
3. THE three-dot menu button SHALL include aria-expanded attribute reflecting menu state
4. THE Export_Menu SHALL include role="menu" attribute
5. THE Export_Menu options SHALL include role="menuitem" attributes
6. THE Horizontal_Bar_Chart SHALL include aria-label describing the chart type and data
7. THE Revenue_Insights_Component SHALL maintain color contrast ratio of at least 4.5:1 for all text

### Requirement 20: Chart Legend Display

**User Story:** As a user, I want to see a legend below the chart, so that I can understand the color coding of different categories.

#### Acceptance Criteria

1. WHEN data is displayed, THE Horizontal_Bar_Chart SHALL show a legend below the chart
2. THE legend SHALL display up to 6 category items in a grid layout
3. THE legend SHALL show a colored square indicator matching the bar color
4. THE legend SHALL show the category name next to the color indicator
5. THE legend SHALL truncate long category names with ellipsis
6. THE legend SHALL use a 2-column grid on mobile and 3-column grid on desktop

### Requirement 21: CSV Export Parser

**User Story:** As a developer, I want a robust CSV parser for export, so that revenue data is correctly formatted for spreadsheet applications.

#### Acceptance Criteria

1. WHEN the Export_Menu is invoked, THE CSV_Parser SHALL parse revenue data into CSV structure
2. THE CSV_Parser SHALL escape special characters (commas, quotes, newlines) in category names
3. THE CSV_Parser SHALL include column headers: Name, Amount, Percentage
4. THE CSV_Parser SHALL format currency values with 2 decimal places
5. THE CSV_Parser SHALL format percentage values with 2 decimal places and "%" suffix

### Requirement 22: CSV Pretty Printer

**User Story:** As a user, I want exported CSV files to be well-formatted, so that they are readable in Excel and other spreadsheet applications.

#### Acceptance Criteria

1. THE CSV_Pretty_Printer SHALL format CSV output with consistent column alignment
2. THE CSV_Pretty_Printer SHALL use UTF-8 encoding for proper character display
3. THE CSV_Pretty_Printer SHALL separate columns with commas and rows with newline characters
4. THE CSV_Pretty_Printer SHALL quote fields containing commas or quotes

### Requirement 23: Round-Trip CSV Property

**User Story:** As a developer, I want to ensure CSV export integrity, so that exported revenue data can be reliably re-imported if needed.

#### Acceptance Criteria

1. FOR ALL valid revenue data objects, THE Export_Menu SHALL generate valid CSV output
2. FOR ALL valid CSV output, parsing then pretty-printing then parsing SHALL produce an equivalent data structure (round-trip property)
3. WHEN CSV generation completes, THE Export_Menu SHALL validate the output format
4. WHEN validation fails, THE Export_Menu SHALL log an error and prevent download

### Requirement 24: Database Query Optimization

**User Story:** As a developer, I want efficient database queries, so that the Revenue Insights component performs well with large datasets.

#### Acceptance Criteria

1. THE Database_Query SHALL use SELECT with specific columns instead of SELECT *
2. THE Database_Query SHALL use appropriate JOINs to minimize query count
3. THE Database_Query SHALL use aggregate functions (SUM, COUNT, AVG) in the database rather than in JavaScript
4. THE Database_Query SHALL use LIMIT clause to retrieve only top 10 items when applicable
5. THE Database_Query SHALL use parameterized queries to prevent SQL injection
6. THE Database_Query SHALL include proper error handling with try-catch blocks

### Requirement 25: Color Scheme Consistency

**User Story:** As a user, I want the Revenue Insights component to match the overall dashboard design, so that the interface feels cohesive.

#### Acceptance Criteria

1. THE Revenue_Insights_Component SHALL use teal (#14B8A6) as the primary color for active states
2. THE Horizontal_Bar_Chart SHALL use teal (#14B8A6) as the default bar color
3. THE Revenue_Insights_Component SHALL use slate colors for text (slate-900, slate-700, slate-600, slate-500)
4. THE Period_Comparison SHALL use green (#10B981) for positive growth
5. THE Period_Comparison SHALL use red (#EF4444) for negative growth
6. THE Period_Comparison SHALL use amber (#F59E0B) for significant changes
7. THE No_Data_State SHALL use slate-300 for icons and slate-600 for text

## Technical Constraints

- Must use React with functional components and hooks
- Must use Recharts library for chart visualization
- Must use Supabase client for all database queries
- Must use Tailwind CSS for styling to match existing dashboard design
- Must integrate into existing Reports.jsx page within the AnalyticsDashboard component
- Must use existing useAnalytics hook for data fetching where applicable
- Must support modern browsers (Chrome, Firefox, Safari, Edge - latest 2 versions)
- Must not exceed 500ms data fetch time per view
- Must not exceed 200ms chart rendering time
- Must handle up to 1,000 data points per view without performance degradation

## Non-Functional Requirements

- All database queries must use parameterized queries to prevent SQL injection
- All user inputs must be validated before use in queries
- All error messages must be user-friendly without exposing technical details
- All exported files must include timestamp in filename for version tracking
- All chart colors must be accessible with sufficient contrast ratios
- Component must be reusable and maintainable with clear prop interfaces
- Component must include JSDoc comments for all functions and props
